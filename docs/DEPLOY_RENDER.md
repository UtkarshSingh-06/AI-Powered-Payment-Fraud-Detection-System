# Deploy FraudShield on Render

One-click deploy using the Render Blueprint. The production
**monolith** service serves the React UI and API on the same URL (best for cookies and simplicity).

## Quick deploy

1. Push this repo to GitHub.
2. Open [Render Dashboard](https://dashboard.render.com) → **New** → **Blueprint**.
3. Connect the repo and select `render.yaml`.
4. After deploy, open the **fraudshield** service URL (e.g. `https://fraudshield-xxxx.onrender.com`).
5. Set **INFERENCE_URL** on the `fraudshield` service to your inference service URL:
   `https://fraudshield-inference-xxxx.onrender.com`
6. Redeploy the main service.

## Required env vars (production)

| Variable | Description |
|----------|-------------|
| `JWT_SECRET` | Auto-generated by Render |
| `DATABASE_URL` | From Render Postgres |
| `INFERENCE_URL` | URL of `fraudshield-inference` service |
| `STRIPE_WEBHOOK_SECRET` | From Stripe Dashboard → Webhooks |
| `STRIPE_SECRET_KEY` | Stripe secret key (test or live) |
| `CORS_ORIGIN` | Your Render app URL (same as monolith if using SERVE_FRONTEND) |

## Stripe webhook

1. Stripe Dashboard → Developers → Webhooks → Add endpoint.
2. URL: `https://YOUR-APP.onrender.com/api/webhooks/stripe`
3. Events: `payment_intent.succeeded`, `payment_intent.payment_failed`, `charge.dispute.created`
4. Add metadata on PaymentIntents:

```json
{
  "tenantId": "default",
  "userId": "user_001",
  "merchantName": "Acme Store",
  "merchantCategory": "Retail"
}
```

5. Copy signing secret → `STRIPE_WEBHOOK_SECRET` on Render.

Local testing:

```bash
stripe listen --forward-to localhost:5000/api/webhooks/stripe
```

## Architecture on Render

| Service | Role |
|---------|------|
| **fraudshield** | API + static frontend + WebSocket |
| **fraudshield-inference** | ML scoring (optional but recommended) |
| **fraudshield-db** | PostgreSQL |

Kafka/microservices are **not** required on Render; scoring runs in-process on the main backend.

## Custom domain

1. Render → fraudshield → Settings → Custom Domain.
2. Set `CORS_ORIGIN=https://yourdomain.com`.
3. Enable HTTPS (automatic on Render).

## Security notes for pilot

- Change demo passwords after first login.
- Set `MFA_DEV_BYPASS=false` when going beyond demo.
- Use Stripe **test mode** until legal/compliance review.
- Never commit `.env` or secrets to git.

## Troubleshooting

| Issue | Fix |
|-------|-----|
| 502 on cold start | Free tier spins down; first request takes ~30s |
| Login fails | Check `DATABASE_URL`; re-run deploy with `SEED_ON_START=true` |
| No ML scores | Set `INFERENCE_URL` and ensure inference service is running |
| Stripe 400 signature | Set `STRIPE_WEBHOOK_SECRET`; use raw body endpoint (already configured) |

## Manual deploy (without Blueprint)

```bash
# Build locally
docker build -f Dockerfile.render -t fraudshield .

# Or connect GitHub repo as Docker Web Service on Render
# Dockerfile path: Dockerfile.render
```
